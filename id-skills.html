Step 1 - Idea to First Sale

The Market Challenge

The Texas Dept. of Licensing & Regulation (TDLR) requires continuing education across 38+ regulated trades, representing a target market of nearly 1 million working professionals in Texas.

Since maintaining these licenses legally requires annual, biannual, or multi-year continuing education, it creates a potential recurring revenue stream. Currently nine different courses are scheduled to be developed, hosted, approved by TDLR, and then marketed.

How Automation Solves It

  • Consistency: standardized, high-quality course structures every time.
  • Speed: drastically reduced course development time.
  • Scale: rapid production and deployment to market.

Step 2 - How a Course Is Made

Build · Pipeline

Automated Curriculum AI Pipeline

Built a multi-agent AI workflow that turns electrical-safety codes (NEC®, NFPA 70E®) into finished Moodle courses.

  • Source data (RAG): Indexed the source codes into a retrieval (RAG) pipeline so the AI answers from cited text, not from model memory.
  • Running the agents: A set of AI agents runs in order to chunk the content, set objectives, draft lessons, and write assessments.
  • Quality gates: A three-part check (fact-check, copyright, QA) reviews every course. Anything it flags, such as a wrong claim or a compliance problem, goes back for a rewrite before the course ships.

Step 3 - Curriculum Development Skills Pipeline

Entry Map · Pipeline

Six AI skills run as a relay, and the baton is a file: each skill reads what the last one wrote, then writes the file the next one picks up.

Start with one expert's raw knowledge, finish with a quality-checked, recordable course. Click any gold skill node to drill into exactly how that step processes information from start to finish, or open the RLO taxonomy to see the reusable lesson "bricks" the pipeline produces.

Stage 1 - id-architect

Detail · Foundation

The architect turns a request into the pipeline's source of truth. It validates the audience across five dimensions (with a GO / NO-GO gate), picks a curriculum series level, writes three to five measurable performance objectives, generates the naming convention, and writes `architect-output.json` - the one file every later skill reads. Follow the steps left to right; the gold node carries you to the next skill.

Stage 2 - id-chunker

Detail · Structure

The chunker reads the architect file plus the raw source text (in batches, to stay inside the context window), classifies each section by content type, scores its intrinsic cognitive load, and assigns each chunk a Reusable Learning Object (RLO) type. It never writes scripts - it produces a reviewed RLO map, `chunker-output.json`, flagging load mismatches and gaps rather than silently fixing them. The gold output node carries you to the scripter; the RLO node opens the full type taxonomy.

Stage 3 - id-scripter

Detail · Authoring

The scripter reads the architect and chunker files and writes production-ready instructional text. First it resolves any chunker flags, then it enforces the language rules, places an Introduction RLO at every structural boundary (its most critical job), writes each RLO using its type-specific template, assembles the whole course, and runs a seven-check quality gate before writing two files. The gold output node carries you to the evaluator; the RLO node opens the type taxonomy.

Stage 4 - id-evaluator

Detail · Assessment

The evaluator reads the architect and scripter files and produces the assessment plus the metadata that makes the course governable. It builds an assessment blueprint (one Assessment Objective per performance objective), picks a modality by series level, writes items against five psychometric core values, applies a seven-facet tag to every RLO, records the reasoning behind key decisions, and assembles the final package. The gold output node carries you to the presenter; this is also the end of the core four-skill pipeline.

Stage 5 - id-presenter

Detail · Narration

The presenter reads the scripter and architect files and rewrites learner-facing scripts into spoken narration a presenter can record. It sets timing parameters (duration target, words-per-minute, per-RLO word budget), converts register from formal to conversational, writes narration with slide and delivery cues for each RLO, calculates actual timing and flags variances over twenty percent, and groups the RLOs into recording sessions. It writes three production files. The gold output node carries you to the QA auditor.

Stage 6 - id-qa-auditor

Detail · Quality Gate

The QA auditor is the quality gate. It reads every pipeline file plus the full wiki reference suite, then runs six independent audits - each with its own source of truth - one at a time with user confirmation between them. It writes three reports and a publication-readiness verdict. It changes nothing in the other files; a FAIL routes work back to the scripter. This is the terminal stage, so there is no forward node - only the path back to the overview.

RLO Taxonomy - Every Reusable Learning Object Defined

Reference · RLO Types

A Reusable Learning Object (RLO) - formerly called a Reusable Content Object (RCO), the name still used in the pipeline's JSON keys like `rco_id` and `rco_type` - is the smallest reusable "brick" of a course. The chunker assigns each chunk one of these types and the scripter writes each from its own template. This map defines every RLO type in four families: mandatory framing, boundary Introductions, the Teach-Show-Do content trio, and the closing object.

Step 4 - Delivery Platform - Moodle LMS

Deliver · Platform

Delivery Platform & Compliance Workflow (TX4HRCE)

Set up course delivery and state reporting on Moodle, turning the state's rules into automated workflows.

  • Enrollment: Automated sign-up, where Stripe handles payment and enrollment ties to the learner's state license number.
  • Compliance rules: Built in the state's requirements (a 50-minute seat-time minimum per module and a 12-month block on repeat credit), both checked before a certificate is issued.
  • Data and reporting: Set up a PostgreSQL database (on DigitalOcean) for learner records, automated the 7-day completion report to the Texas Department of Licensing and Regulation (TDLR), and gave auditors a read-only dashboard with the required 4-year record retention.
